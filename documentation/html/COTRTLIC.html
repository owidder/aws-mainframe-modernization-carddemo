COTRTLIC.CBL

Provides an interactive screen for bank administrators to browse, search, select, and initiate updates or deletions of Transaction Type reference data records.

This CICS online program presents a paginated list of Transaction Type codes and their descriptions from the TRANSACTION_TYPE reference table, allowing administrators to browse up to 7 records per screen page. Users can filter the list by transaction type code or description, then select individual records for update (action code 'U') or deletion (action code 'D'). Only one action may be selected at a time; selecting a record for update navigates to the COTRTUPC update program, while deletion requires confirmation via F10 before the record is removed. The program enforces data integrity by validating user input, detecting changes, and providing informational messages to guide the user through each step of the maintenance workflow.

Business Rules
  • Only one action (update or delete) may be selected at a time across all displayed rows; selecting more than one triggers an error message 'Please select only 1 action'.
  • Valid action codes are strictly 'U' (update) or 'D' (delete); any other non-blank entry is rejected with 'Action code selected is invalid'.
  • A deletion requires explicit confirmation by pressing F10 after the record is highlighted; the record is not deleted on initial selection alone.
  • An update action navigates the user to the COTRTUPC program (transaction CTTU) passing the selected transaction type code for editing.
  • If no records match the current search/filter criteria, the message 'No records found for this search condition.' is displayed and no action is permitted.
  • If the user attempts to save an update but no data has actually changed compared to the database values, the system rejects the save with 'No change detected with respect to database values.'
  • The screen displays a maximum of 7 transaction type records per page; paging is implemented using DB2 cursors with a start key to support forward navigation through the reference table.
  • Filter criteria (type code and/or description) can be combined to narrow search results; changes to filter values reset the paging position.
  • The program enforces that transaction type descriptions are non-blank and contain only valid alphanumeric characters before allowing an update to be saved.
  • Upon successful deletion or update, a confirmation message is displayed and the list is refreshed to reflect the current state of the reference table.
