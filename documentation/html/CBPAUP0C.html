CBPAUP0C.CBL

Cleanup of expired, outstanding authorization messages from the credit card authorization database by deleting outdated entries.

The program iterates through all Pending Authorization Summaries in the IMS database and checks for each associated detail entry whether the authorization has exceeded the configured expiration date. Expired detail entries are deleted, with approved and rejected authorizations corrected accordingly in the summary counters and amounts. If after cleanup a summary contains neither approved nor rejected authorizations, the parent summary record is also deleted. The process runs as a nightly or periodic batch job with configurable checkpoint intervals for restart/recovery capability.

Business Rules
  • A pending authorization is considered expired when the difference between the current date and the authorization date is greater than or equal to the configured expiry value (default: 5 days).
  • When deleting an expired detail record, the counters and amounts in the parent summary record are updated: approved entries (response code '00') reduce the approval counter and amount, while all other entries reduce the rejection counter and amount.
  • A summary record is deleted only when both the approved authorization counter and the rejected authorization counter have dropped to zero or below (fully cleaned-up account).
  • The batch job sets IMS checkpoints at configurable intervals to enable a restart without data loss or duplicate processing in the event of a program failure.
  • If the expiry parameter is not provided as a numeric value, a default of 5 days is applied as a safety net.
  • On any database error (read or delete), the program terminates in a controlled manner with return code 16 to prevent data inconsistencies.
  • At the end of processing, the program outputs a complete processing statistics report (summary and detail records read/deleted) for audit and monitoring purposes.
