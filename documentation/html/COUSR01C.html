COUSR01C.CBL

Add a new Regular or Admin user account to the CardDemo system's user security file.

This program presents a data entry screen to an authorised administrator, allowing them to create a new user account in the CardDemo system. The administrator must supply the new user's first name, last name, user ID, password, and user type (Regular or Admin). Upon submission, the program validates that all fields are populated, checks that the user ID does not already exist, and if all validations pass, writes the new user record to the USRSEC security file. Success or failure feedback is displayed on screen, and duplicate user IDs are explicitly rejected to maintain uniqueness of user accounts.

Business Rules
  • First Name is mandatory — a new user account cannot be created without a first name.
  • Last Name is mandatory — a new user account cannot be created without a last name.
  • User ID is mandatory — a new user account cannot be created without a user ID.
  • Password is mandatory — a new user account cannot be created without a password.
  • User Type is mandatory — the access level (Regular or Admin) must be specified for every new user.
  • User ID must be unique — if the User ID already exists in the USRSEC file, the record is rejected with a 'User ID already exists' error and no duplicate record is written.
  • Only authenticated and authorised users (administrators) can access this program; unauthenticated sessions are redirected to the sign-on screen (COSGN00C).
  • Upon successful creation, the entry form is cleared and a confirmation message is displayed, allowing the administrator to add another user immediately.
  • PF3 navigates back to the Admin menu (COADM01C); PF4 clears the current screen without saving; any other key press is treated as invalid.
Files / Data Sources
USRSEC User security file storing all CardDemo user account credentials and access type (Regular/Admin)

Paragraph Overview

MAIN-PARA

MAIN-PARA is the central orchestration paragraph that controls the entire user-add session flow. It determines whether to present the data entry screen, process a submitted form, or redirect the administrator based on their key press or session state.

Lines 71–114

PROCESS-ENTER-KEY

This paragraph enforces all mandatory field validations when an administrator submits a new user creation request, and if all fields are valid, writes the new user account to the security file. It acts as the central gate-keeper ensuring no incomplete or duplicate user records are ever persisted.

Lines 115–164

RETURN-TO-PREV-SCREEN

This paragraph handles navigation away from the Add User screen, transferring control back to the appropriate previous screen — defaulting to the sign-on screen if no specific destination was recorded. It packages the current transaction's identity into the shared communication area before handing off control.

Lines 165–183

SEND-USRADD-SCREEN

This paragraph prepares and displays the Add User data entry screen to the administrator, including any status or error messages resulting from a previous submission attempt. It ensures the screen is fully refreshed with current feedback before awaiting the next administrator input.

Lines 184–200

RECEIVE-USRADD-SCREEN

This paragraph captures the data entered by the administrator on the Add User screen, retrieving all typed field values (first name, last name, user ID, password, and user type) so they can be validated and processed to create the new user account.

Lines 201–213

POPULATE-HEADER-INFO

This paragraph prepares the header section of the Add User screen with contextual information — application titles, the active transaction identifier, the program name, and the current date and time — so that the administrator sees a fully labelled and timestamped screen before entering new user details.

Lines 214–237

WRITE-USER-SEC-FILE

This paragraph attempts to permanently save the new user account to the security file and then provides the administrator with immediate feedback — either confirming successful creation, rejecting a duplicate User ID, or reporting an unexpected system failure.

Lines 238–278

CLEAR-CURRENT-SCREEN

Resets the user account creation form to a blank state, ready for a new entry. This is triggered when an administrator explicitly requests a screen clear (PF4) without saving any data entered.

Lines 279–286

INITIALIZE-ALL-FIELDS

Resets the user account creation form to a blank state, clearing all previously entered data and any status messages. This is used to prepare the screen for a fresh user account entry, either after a successful creation or when the administrator explicitly clears the form.
