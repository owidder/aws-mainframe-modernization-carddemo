DBUNLDGS.CBL

Unload of outstanding authorization data from the IMS database into sequential GSAM output files for archiving or further processing.

The program fully reads all outstanding credit card authorization records from a hierarchical IMS database. It processes a two-level hierarchy: for each authorization summary record (summary/root segment, e.g., account information), all associated authorization detail records (child segments) are read. Both the summary records and the detail records are written to separate GSAM output files (Sequential Access Method for IMS), with the account key serving as the linking key. The program typically serves as the first step in a batch processing cycle to provide authorization data for downstream processes (e.g., cleanup, migration, reporting).

Business Rules
  • Only authorization summary records with a valid (numeric) account number (PA-ACCT-ID IS NUMERIC) are written to the output file and their detail records are processed.
  • The hierarchical relationship between account summary and authorization details is preserved: detail records are only read in the context of their parent summary record (GNP – Get Next within Parent).
  • In the event of a database error (status not equal to spaces or end-of-file), the program terminates with return code 16 (hard abend) to prevent data loss or inconsistent output.
  • The program processes all pending authorizations in full (Full Unload) without filtering by date or status – it is a complete data extract of the entire pending authorization database.
  • The checkpoint mechanism (RMAD prefix) is intended for batch restart capability, allowing the run to be resumed in the event of an abend.

MAIN-PARA

MAIN-PARA is the central control framework of the batch run: it orchestrates the complete unload process of all pending credit card authorization data from the IMS database into the sequential output files.

4000-FILE-CLOSE

This paragraph closes the GSAM output files for summary and detail records after the complete data extract has finished. The actual close logic is currently disabled, as GSAM files in IMS are managed via the PCB mechanism and do not require an explicit CLOSE.

Emergency abort routine: in the event of a critical error (e.g., a database error), the batch run is terminated in a controlled manner to prevent data loss or inconsistent output in the authorization files.

Formal end point of the program, signaling the orderly completion of the full pending authorization database extract and returning control to the calling batch process.
