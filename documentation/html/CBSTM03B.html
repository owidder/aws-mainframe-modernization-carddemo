CBSTM03B.CBL

A reusable batch file-access subroutine that provides controlled read access to transaction, card cross-reference, customer, and account data files on behalf of the Transaction Report generation process.

CBSTM03B acts as a centralised file I/O handler called by a parent batch reporting program (the 'statement create program') to retrieve the raw data needed to produce a Transaction Report. The subroutine accepts a file identifier, an operation code (Open, Close, Sequential Read, or Keyed Read), an optional lookup key, and a data buffer through its linkage interface, then performs the requested file operation and returns the data along with a status code to the caller. Transaction and cross-reference files are read sequentially (full file scan), while customer and account files are accessed randomly by key, allowing the parent program to enrich each transaction record with the corresponding customer name and account details. By isolating all file handling in this single subroutine, the system enforces a consistent, auditable access pattern across all four master data sources used in transaction reporting.

Business Rules
  • Only read (INPUT) access is permitted to all four files – no inserts, updates, or deletions are allowed, preserving data integrity during report generation.
  • Transaction and cross-reference files are read sequentially (full file scan), ensuring every transaction in the reporting period is included without omission.
  • Customer and account records are retrieved by explicit key lookup only, meaning a valid cross-reference must exist before customer or account data can be enriched onto a transaction.
  • The subroutine returns a file status code to the caller after every operation, enabling the parent program to detect and handle missing records, end-of-file conditions, or I/O errors without aborting the entire report run.
  • The subroutine is file-agnostic by design – the caller selects the target file via a DD name parameter, enforcing a single, consistent I/O interface across all data sources used in transaction reporting.
  • A maximum of four files (transactions, card cross-reference, customers, accounts) are in scope, reflecting the complete set of data entities required to produce a fully enriched Transaction Report.
Files / Data Sources
TRNXFILE Credit card transaction history file – the primary source of individual transaction records used to build the Transaction Report
XREFFILE Card-to-account cross-reference file – maps a credit card number to its associated account, enabling account lookup from a card-based transaction
CUSTFILE Customer master file – provides customer identity and demographic details to enrich transaction report lines with cardholder information
ACCTFILE Account master file – provides account-level financial details (limits, balances, status) to enrich the Transaction Report with account context
