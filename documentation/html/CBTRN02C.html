CBTRN02C.CBL

Batch program that validates and posts daily credit card transactions to the permanent transaction ledger, updating account balances and transaction category balances, while routing invalid transactions to a rejection file.

CBTRN02C reads each transaction from the daily transaction input file and performs validation checks against the card cross-reference and account master files. Valid transactions are posted to the permanent indexed transaction file and the account balance is updated accordingly, with spending also accumulated by transaction category. Invalid transactions that fail validation are written to a daily rejects file with a reason code and description explaining the failure, and a non-zero return code is set if any rejections occur to alert downstream processes.

Business Rules
  • Every transaction must be validated before posting; a transaction that fails any validation check is never posted to the permanent ledger.
  • A failed transaction is written to the daily rejects file with a numeric reason code and descriptive text so that operations staff can identify and remediate the problem.
  • The card number on each transaction must exist in the card-to-account cross-reference file; transactions with an unrecognised card number are rejected.
  • The resolved account must exist and be in good standing in the account master file; transactions against invalid or non-existent accounts are rejected.
  • Successfully posted transactions update the account master balance in real time within the batch run, ensuring the account file reflects the day's activity.
  • Spending is accumulated by transaction category (account + transaction type + category code) in the TCATBAL file; if no category balance record exists yet for that combination, a new one is created.
  • The batch job sets a return code of 4 if one or more transactions were rejected, enabling job scheduling software to trigger exception handling or alerts.
  • All files must open successfully before processing begins; any file open failure causes an immediate abnormal termination (ABEND) of the program.
  • Transaction counts (processed and rejected) are displayed at end of job to provide an audit trail of the batch run's results.
