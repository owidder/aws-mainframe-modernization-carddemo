CBEXPORT.CBL

Export complete customer, account, card, cross-reference, and transaction data from the CardDemo system into a structured migration file to support branch migration initiatives.

CBEXPORT is a batch data migration program that reads all normalised CardDemo source files sequentially and consolidates them into a single multi-record-type export file, where each record is tagged with a type indicator (C=Customer, A=Account, etc.) along with a branch identifier, region code, and timestamp. The program processes each data domain in turn — customers, accounts, cross-references, transactions, and cards — writing one export record per source record in a fixed 500-character format with a unique sequence number. Throughout processing, the program accumulates per-entity and total export counts, which are reported at completion to provide an audit trail of the migration run. The output file is intended for consumption by a receiving system (e.g. a new branch platform), with the companion program CBIMPORT likely performing the corresponding load operation at the destination.

Business Rules
  • All five source data domains (customers, accounts, cross-references, transactions, cards) must be successfully opened before any export processing begins; failure to open any file causes immediate program termination.
  • Every exported record is stamped with the branch ID '0001' and region code 'NORTH', indicating this export is scoped to a specific branch migration event and is not a generic full-system export.
  • Each export record receives a globally unique, monotonically increasing sequence number across all record types, enabling the receiving system to detect gaps, duplicates, or ordering issues during import.
  • Sensitive customer identity data — including Social Security Number (SSN), government-issued ID, date of birth, and FICO credit score — is exported in full without masking, requiring strict access controls on the export file.
  • Any I/O error during reading of source files or writing of the export file causes immediate abnormal program termination (ABEND), ensuring no partial or corrupt migration file is silently accepted.
  • The export processes each entity type as a complete, independent pass through its source file (sequential full-file reads), meaning the export captures a point-in-time snapshot per entity type rather than a single consistent snapshot across all entities simultaneously.
  • Export statistics (record counts per entity type and total) are displayed at job completion, providing an operational audit record for reconciliation against the import counts in the receiving system.
