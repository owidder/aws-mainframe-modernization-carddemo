COTRTUPC.CBL

Provides an interactive CICS screen for bank administrators to add, update, or delete Transaction Type reference data records in the database.

COTRTUPC is the online update/maintenance program for the Transaction Type reference table, working in tandem with the list/browse program COTRTLIC. A bank administrator can search for a transaction type by its 2-character code, view its current description, and then choose to modify the description, delete the record, or create a new transaction type entry. The program enforces a multi-step confirmation workflow: changes are first validated, then presented for confirmation before being committed to the database, and deletions require an explicit F4 confirmation step to prevent accidental removal. It maintains data integrity by detecting concurrent modifications (record changed by another user) and locking records during the update process.

Business Rules
  • Transaction type codes are exactly 2 characters and must be alphanumeric — blank or invalid codes are rejected with an appropriate error message.
  • Transaction type descriptions are up to 50 characters; blank descriptions are not permitted for active records.
  • A multi-step confirmation is required for updates: changes are validated first, displayed for review, and only committed to the database after the administrator explicitly presses F5 to confirm.
  • Deletions require a separate explicit confirmation step (F4) to prevent accidental removal of transaction type reference data.
  • The program detects concurrent modification: if the record has been changed by another user between the time it was fetched and the time the update is submitted, the administrator is warned and the update is rejected.
  • If the database record cannot be locked for update, the operation is aborted and the administrator is notified.
  • No changes are committed if the administrator's input is identical to the values originally retrieved from the database (no-change detection).
  • The administrator can cancel an in-progress update or delete at any point, returning the system to a safe state with an appropriate cancellation message.
  • Navigation is controlled via PF keys: F3 exits to the admin menu, F12 cancels the current operation, and invalid PF key presses are rejected with an error message.
  • The program participates in the broader admin workflow, receiving context from COTRTLIC (list screen) and returning control to the admin menu (COADM01C) upon exit.
