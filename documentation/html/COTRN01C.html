COTRN01C.CBL

Display the full details of a single credit card transaction retrieved from the TRANSACT file by Transaction ID.

This program allows a bank operator or customer service representative to look up and view the complete details of a specific credit card transaction by entering its Transaction ID. Upon receiving a valid Transaction ID, the program retrieves the transaction record from the TRANSACT file and displays all associated details including the card number, transaction type, category, source, amount, description, origination and processing timestamps, and merchant information (ID, name, city, ZIP code). The program is typically invoked from the transaction list screen (COTRN00C), where a specific transaction has been selected, and supports navigation back to the calling screen or to the transaction list. If the Transaction ID is not found or is left blank, appropriate error messages are displayed to the user.

Business Rules
  • Transaction ID is mandatory; the system will not attempt a lookup and will display an error message if the field is left blank.
  • If the entered Transaction ID does not exist in the TRANSACT file, the user is informed with a 'Transaction ID NOT found' message and no transaction details are displayed.
  • When navigated from the transaction list screen (COTRN00C), the selected Transaction ID is automatically populated and the lookup is performed without requiring manual entry.
  • The program reads the transaction record with an UPDATE intent (CICS READ UPDATE), suggesting the record may be locked for potential downstream editing, even though this screen is view-only.
  • Navigation via PF3 returns the user to the originating program (or the main menu if no originating program is recorded); PF5 returns directly to the transaction list screen (COTRN00C); PF4 clears all fields on the current screen.
  • Any unrecognised key press is rejected with an 'invalid key' message, enforcing controlled navigation.
  • If the program is accessed without a valid communication area (e.g., direct access without prior sign-on), the user is redirected to the sign-on screen (COSGN00C), enforcing authentication requirements.

MAIN-PARA

MAIN-PARA is the central orchestration routine of the transaction detail viewer. It determines the user's context and intent — whether they are arriving for the first time, returning after an action, or pressing a navigation key — and routes processing accordingly to display, look up, or navigate away from a credit card transaction's full details.

269 EXEC CICS READ Initiates a request to retrieve a transaction record from the master transaction file, locking it for potential downstream editing.
270 DATASET (WS-TRANSACT-FILE) Identifies the master transaction file as the source of the lookup.
271 INTO (TRAN-RECORD) Specifies that the retrieved transaction record should be loaded into the working area holding all transaction details (card number, amount, merchant info, timestamps, etc.).
272 LENGTH (LENGTH OF TRAN-RECORD) Defines the expected size of the transaction record to be retrieved.
273 RIDFLD (TRAN-ID) Specifies that the lookup should be performed using the Transaction ID entered by the operator as the search key.
274 KEYLENGTH (LENGTH OF TRAN-ID) Defines the exact length of the Transaction ID field used to locate the record.
275 UPDATE Instructs the system to lock the retrieved record, reserving it against concurrent modification by other users or processes.
276 RESP (WS-RESP-CD) Captures the primary outcome code returned by the system after the retrieval attempt, indicating success or failure.
277 RESP2 (WS-REAS-CD) Captures a secondary diagnostic code providing additional detail about the reason for any failure.
278 END-EXEC.
