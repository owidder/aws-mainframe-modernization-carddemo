COUSR03C.CBL

Allow administrators to look up and permanently delete an existing user account from the CardDemo system's user security file.

The program presents an administrator with a user deletion screen where they can enter a User ID to look up. Upon entering a User ID and pressing Enter, the system retrieves and displays the user's details (first name, last name, user type) from the security file, prompting the administrator to confirm deletion. The administrator must then explicitly press PF5 to confirm and execute the permanent deletion of the user account. Upon successful deletion, the screen is cleared and a confirmation message is displayed; the administrator can cancel at any time by pressing PF3 or PF12 to return to the previous screen.

Business Rules
  • A User ID must be provided before any lookup or deletion can be performed; an empty User ID is rejected with an error message.
  • The administrator must perform a two-step confirmation: first look up the user (Enter key) to verify the correct account is displayed, then explicitly press PF5 to execute the permanent deletion.
  • If the specified User ID does not exist in the security file, the deletion is rejected with a 'User ID NOT found' error message.
  • Deletion is permanent and irreversible; once confirmed via PF5, the user record is removed from the USRSEC file with no soft-delete or archival mechanism.
  • The program can only be accessed from within an authenticated session; if no communication area is present (EIBCALEN = 0), the user is redirected to the sign-on screen (COSGN00C).
  • Upon successful deletion, all screen fields are cleared, preventing accidental re-submission or confusion about the current state.
  • PF3 and PF12 both return the administrator to the previous screen (typically the admin menu COADM01C), allowing cancellation without deletion.
  • PF4 clears the current screen input, allowing the administrator to start a new lookup without navigating away.
  • The program uses a CICS UPDATE lock when reading the user record prior to deletion, ensuring no concurrent modifications can occur between the lookup and the delete operation.

Paragraph Overview

MAIN-PARA

MAIN-PARA is the central orchestration paragraph of the user deletion program. It determines the session context, interprets the administrator's input, and routes processing to the appropriate action — whether that is displaying the deletion screen, looking up a user, confirming deletion, clearing the screen, or returning to the previous menu.

Lines 82–141

PROCESS-ENTER-KEY

This paragraph handles the administrator's initial User ID lookup request by validating that a User ID has been entered, retrieving the matching user account from the security file, and displaying the account details (name and user type) on screen so the administrator can confirm they are deleting the correct person.

Lines 142–173

DELETE-USER-INFO

This paragraph orchestrates the user account deletion process by first validating that a User ID has been provided, then retrieving the user record from the security file and permanently removing it. It acts as the central coordinator for the two-step deletion workflow, enforcing mandatory input before any file operations are attempted.

Lines 174–196

RETURN-TO-PREV-SCREEN

This paragraph handles the navigation logic when an administrator cancels or completes the user deletion process, transferring control back to the appropriate previous screen. It ensures the system always has a valid destination to return to, defaulting to the sign-on screen if no prior navigation context exists.

Lines 197–212

SEND-USRDEL-SCREEN

This paragraph renders the User Deletion screen to the administrator's terminal, displaying any relevant status or error messages alongside the current screen data. It is the final step in preparing the visual interface before the administrator can enter a User ID or confirm a deletion.

Lines 213–229

RECEIVE-USRDEL-SCREEN

This paragraph captures the administrator's input from the user deletion screen, reading whatever the administrator has typed or the function key they have pressed. It is the entry point for processing any administrator action on the delete user form, whether that is entering a User ID to look up, confirming a deletion, or cancelling.

Lines 230–242

POPULATE-HEADER-INFO

Populates the header section of the user deletion screen with current date, time, application title, transaction identifier, and program name, ensuring the administrator always sees accurate contextual information at the top of the screen before any user lookup or deletion action is performed.

Lines 243–266

READ-USER-SEC-FILE

This paragraph retrieves a user account from the security file using an exclusive lock, preventing concurrent changes, and displays the account details to the administrator for deletion confirmation. Depending on whether the account is found or not, it either prompts the administrator to confirm deletion via PF5, or displays an appropriate error message.

Lines 267–304

DELETE-USER-SEC-FILE

This paragraph executes the permanent, irreversible deletion of a user account from the security file and handles all possible outcomes: confirming success to the administrator, reporting that the user was not found, or surfacing an unexpected system error.

Lines 305–340

CLEAR-CURRENT-SCREEN

Resets the user deletion screen to a blank state after a deletion is completed or when a fresh lookup is needed, preventing any residual user data from remaining visible and avoiding accidental re-submission. This ensures the administrator sees a clean, empty form ready for the next action.

Lines 341–348

INITIALIZE-ALL-FIELDS

Resets the user deletion screen to a completely blank state, clearing all previously displayed user details and any status messages. This ensures the administrator starts with a clean slate, preventing confusion or accidental re-use of data from a prior lookup or deletion.
