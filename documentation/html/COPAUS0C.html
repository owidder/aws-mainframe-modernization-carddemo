COPAUS0C.CBL

Overview display of pending authorization messages for a credit card account with scrolling functionality and drill-down into detail view.

The program provides clerks with a paginated list view of all open/pending authorization requests (Pending Authorizations) for an entered credit card account. The user enters an account number, whereupon the program loads the associated account, customer, and card master data and retrieves the pending authorization records from an IMS database – up to 5 entries per page. Selecting an individual entry (flag 'S') redirects the user to the detail view (COPAUS1C), where complete information on the respective authorization can be viewed. Navigation is handled via function keys: PF7 (previous page), PF8 (next page), PF3 (return to main menu).

Business Rules
  • The account number (Account ID) is a mandatory field and must be numeric – empty or non-numeric inputs are rejected with an error message.
  • A maximum of 5 pending authorization entries are displayed per screen page.
  • For the detail view, only selection code 'S' (Select) is valid – any other value results in an error message.
  • Backward navigation (PF7) is only possible if the current page number is greater than 1 – on the first page, a corresponding informational message is displayed.
  • Page navigation keys (IMS keys) are stored in the communication area for up to 20 previous pages to enable correct backward navigation.
  • On the initial call (EIBCALEN = 0), the communication area is initialized and an empty overview screen is displayed.
  • The mapping from account number to card number and customer data is performed via cross-reference files (CCXREF/CXACAIX) – if an entry is missing, no authorization record is displayed.
  • In the event of database errors (IMS status codes BA, FH, TE), a retry mechanism is triggered.
  • PF3 always returns to the main menu (COMEN01C), regardless of the current display state.

MAIN-PARA

MAIN-PARA is the central control paragraph of the program: it detects the call context (initial call vs. return), evaluates the function key pressed, and thereby controls the entire processing logic of the pending authorization overview.

Positions the IMS database to a previously saved authorization entry in order to resume the list view at the correct position in the authorization history after a page change.

Lines 488–521

POPULATE-AUTH-LIST

Formats a single pending authorization entry for screen display and places it in the correct list position (1–5) of the current overview page. Amount, date, time, authorization type, approval status, and reconciliation status are formatted to be readable by the clerk.

Lines 522–607

INITIALIZE-AUTH-DATA

Resets all five display rows of the authorization overview to a blank, neutral initial state. This ensures that no outdated authorization data from the previous screen remains visible when the next page is built.

Lines 608–664

RETURN-TO-PREV-SCREEN

This paragraph controls the return to the previous application or to the sign-on screen. It transfers control to the calling program and passes along the origin information of the current session.

Lines 665–680

SEND-PAULST-SCREEN

This paragraph displays the formatted overview list of pending authorizations on the screen. It cleanly closes any open IMS database resources beforehand and sends the paginated list map with all header data, authorization entries, and any error messages to the clerk.

Lines 681–711

RECEIVE-PAULST-SCREEN

Receives the pending authorization overview map filled in by the clerk – including the entered account number, selection indicator ('S'), and function key pressed – and makes these inputs available for further processing.

Lines 712–725

POPULATE-HEADER-INFO

Populates the header area of the overview map with program identification data as well as the current system date and time, so that the clerk can always identify which program they are using and when the display was generated.

Lines 726–749

GATHER-ACCOUNT-DETAILS

This paragraph loads all relevant master and transaction data for a credit card account and prepares it for display on the overview screen. It consolidates account, customer, card, and authorization data into a complete clerk view.

Lines 750–811

GETCARDXREF-BYACCT

Determines the card number and customer number associated with an entered account number via the cross-reference index, in order to establish the link between account, card, and cardholder.

Lines 812–864

GETACCTDATA-BYACCT

Loads the account master record for the entered account number from the account master file (ACCTDAT) in order to provide the credit limit, balance, and account status for the overview display. If the account is not found or cannot be read, a meaningful error message is displayed to the clerk.

Lines 865–914

GETCUSTDATA-BYCUST

Loads the customer master record using the customer number retrieved from the cross-reference, in order to provide the customer data (name, address) for the display overview. If the access fails, a meaningful error message is displayed to the clerk on the overview map.

Lines 915–965

GET-AUTH-SUMMARY

Retrieves the summary segment of pending authorizations for the entered credit card account from the IMS database. This record is a prerequisite for the subsequent display of the authorization list and confirms whether any pending authorization data exists for the account at all.

Lines 966–1000

SCHEDULE-PSB

Establishes the connection to the IMS database (PSBPAUTB) in order to subsequently retrieve the pending authorization data for the credit card account. If a database access is already active, it is first cleanly terminated and then re-established.
