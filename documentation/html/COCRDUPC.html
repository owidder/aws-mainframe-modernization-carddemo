COCRDUPC.CBL

This program allows bank staff to update credit card details (cardholder name, expiry date, and active status) for an existing credit card through a validated, confirmation-based online screen workflow.

Bank staff first retrieve a specific credit card record by entering an account number and card number; the program displays the current card details on screen for review. Staff can then modify editable fields — the embossed cardholder name, card expiry month/year, and card active status (Y/N) — after which the program validates all changes before presenting them for confirmation. Upon confirmation (F5), the program locks the card record, checks it has not been changed by another user in the interim, and commits the update to the card database; if locking or saving fails, an appropriate error is shown and the update is rolled back.

Business Rules
  • Account number is mandatory, must be numeric, exactly 11 digits, and non-zero before a card record can be retrieved
  • Card number is mandatory, must be numeric and exactly 16 digits
  • Embossed cardholder name is mandatory and may only contain alphabetic characters and spaces (no numbers or special characters)
  • Card active status must be either 'Y' (active) or 'N' (inactive); no other values are permitted
  • Card expiry month must be a valid calendar month between 1 and 12
  • Card expiry year must fall within the range 1950 to 2099
  • A two-step confirmation workflow is enforced: changes are validated first, then staff must explicitly confirm (F5) before the database is updated
  • Before committing an update, the program compares the current database record against the originally retrieved snapshot to detect concurrent modification by another user; if the record has changed, the update is rejected and staff are asked to re-review
  • The card record must be successfully locked before any update is applied; failure to lock prevents the update from proceeding
  • If no changes are detected between the original retrieved values and the values submitted by staff, the update is not processed and staff are informed
  • The program supports navigation back to the card list screen (COCRDSLC) or the main menu, allowing staff to exit without saving
