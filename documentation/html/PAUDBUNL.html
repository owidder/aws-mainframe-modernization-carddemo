PAUDBUNL.CBL

Unload all pending authorization data (summary and detail records) from the IMS database into sequential output files for archiving, backup, or downstream processing.

PAUDBUNL reads all pending authorization summary records (PAUTSUM0 segments) sequentially from the IMS database and writes each valid summary record to a sequential output file (OPFILE1). For each summary record found, the program then retrieves all associated child detail records (PAUTDTL1 segments) using a Get-Next-within-Parent (GNP) call and writes them to a second sequential output file (OPFILE2), preserving the parent-child relationship via the account ID as the root segment key. The process continues until all pending authorization records have been exhausted from the database, effectively producing a full snapshot of the pending authorization database in flat file format. This program is the counterpart to PAUDBLOD (which loads data into IMS) and is functionally similar to DBUNLDGS, together forming the unload side of the pending authorization database maintenance cycle.

Business Rules
  • Only pending authorization summary records with a numeric account ID (PA-ACCT-ID IS NUMERIC) are written to the output file and have their child detail records processed — non-numeric account IDs are silently skipped.
  • The parent-child relationship between authorization summary and detail records is preserved in the output by writing the account ID (ROOT-SEG-KEY) alongside each detail record in OPFILE2.
  • All detail records belonging to a summary record are extracted using IMS GNP (Get-Next-within-Parent) calls, ensuring only details associated with the current summary are included before moving to the next account.
  • The program performs a full unload of the entire pending authorization database — no date-based or status-based filtering is applied during the unload itself, making it a complete snapshot.
  • Any unexpected IMS status code (other than spaces for success or GB for end-of-database on summary, or GE for no-more-children on detail) causes an immediate program abend with return code 16, ensuring data integrity of the output files.
  • Checkpoint/restart capability is built in via IMS checkpoint frequency parameters (P-CHKP-FREQ), supporting recovery in case of mid-run failure without reprocessing the entire database.
Files / Data Sources
OPFILE1 Sequential output file containing pending authorization summary records (one record per account/authorization header)
OPFILE2 Sequential output file containing pending authorization detail records (individual transaction-level authorization entries, linked to summary records by account ID key)

Paragraph Overview

MAIN-PARA

MAIN-PARA is the top-level orchestrator of the pending authorization unload process. It initializes the environment, drives the sequential extraction of all pending authorization summary and detail records from the IMS database into output files, then closes those files and returns control to the caller.

9999-ABEND

This paragraph handles unrecoverable errors during the pending authorization unload process by signalling a critical failure and halting the program immediately. It ensures that any unexpected IMS database condition is surfaced as a hard failure, preventing incomplete or corrupted output files from being silently passed to downstream systems.
