CBSTM03A.CBL

Batch program that generates periodic credit card account statements from transaction data, producing output in both plain text and HTML formats.

CBSTM03A reads transaction data from a transaction file and cross-references it with customer and account data to produce formatted account statements. For each credit card account, it collects up to 10 transactions per card (supporting up to 51 cards in a batch run), calculates total expenditure, and formats a complete statement including customer name, address, account ID, current balance, FICO credit score, and an itemised transaction summary. The program produces two output files simultaneously: a fixed-width 80-character plain text statement file and a styled HTML statement file suitable for digital delivery or web rendering. It delegates all physical file I/O operations (open, close, read, write) to the subroutine CBSTM03B, acting as the orchestrating controller for the statement generation process.

Business Rules
  • Each account statement must include customer identification details (name and full address), account ID, current balance, and FICO credit score.
  • The transaction summary section lists each transaction with its unique transaction ID, transaction details/description, and individual transaction amount in USD.
  • A total expenditure figure is calculated and printed at the bottom of the transaction summary, representing the sum of all transactions in the statement period.
  • Statements are generated simultaneously in two formats (plain text and HTML) to support both print/mail and digital delivery channels.
  • The program supports batch processing of up to 51 credit card accounts per run, with a maximum of 10 transactions stored in memory per card before flushing to the statement output.
  • All file operations (open, read, write, close) for source data files are delegated to the CBSTM03B subroutine, enforcing a separation between statement formatting logic and file I/O handling.
  • The program logs the executing JCL job name and step name at startup, providing an audit trail identifying which scheduled batch job produced the statements.
  • Transaction amounts are displayed with a sign indicator to distinguish credits from debits on the customer statement.
  • The HTML statement uses the bank identity 'Bank of XYZ' with address '410 Terry Ave N, Seattle WA 99999', indicating a configurable bank branding requirement for digital statements.
