COSGN00C.CBL

Authenticates users logging into the CardDemo credit card management system and routes them to the appropriate menu based on their user type.

This program presents a sign-on screen to users, collecting their User ID and Password credentials. It validates the entered credentials against a User Security file (USRSEC), checking that the user exists and that the supplied password matches the stored password. Upon successful authentication, it determines whether the user is an administrator or a regular user and routes them accordingly — administrators are directed to the Admin Menu (COADM01C) and regular users to the Main Menu (COMEN01C). If authentication fails due to a missing User ID, missing password, incorrect password, or unknown user, the sign-on screen is redisplayed with an appropriate error message.

Business Rules
  • User ID is mandatory — the system will not attempt authentication if the User ID field is blank
  • Password is mandatory — the system will not attempt authentication if the Password field is blank
  • Both User ID and Password are converted to uppercase before validation, making authentication case-insensitive
  • A user must exist in the User Security file; if not found, access is denied with a 'User not found' message
  • The supplied password must exactly match the password stored in the User Security file; a mismatch results in a 'Wrong Password' error and the user must retry
  • Authenticated users are routed to different menus based on their user type: administrators go to the Admin Menu (COADM01C), regular users go to the Main Menu (COMEN01C)
  • Pressing PF3 at the sign-on screen displays a 'Thank You' message and terminates the session gracefully
  • Any key other than Enter or PF3 is rejected with an 'Invalid Key' error message, preventing unintended navigation
  • System errors during credential lookup (i.e. any response code other than 'found' or 'not found') result in an 'Unable to verify the User' message, preventing access without exposing technical details

Paragraph Overview

MAIN-PARA

MAIN-PARA is the central orchestration paragraph of the sign-on process. It determines whether a user is arriving at the screen for the first time or responding to it, then routes control based on the key pressed — presenting the sign-on screen, processing credentials, accepting a graceful exit, or rejecting invalid input — before returning control to the transaction to await the next user interaction.

Lines 73–107

PROCESS-ENTER-KEY

This paragraph handles the user's login submission by collecting and validating the credentials entered on the sign-on screen. It enforces mandatory field rules, normalises the credentials to uppercase for case-insensitive comparison, and triggers the lookup of the user's record in the security file if all basic validations pass.

Lines 108–144

SEND-SIGNON-SCREEN

Prepares and displays the sign-on screen to the user, including any error or informational message resulting from a failed or initial authentication attempt. This paragraph is the final step in presenting the login interface, ensuring the user sees current feedback before re-entering credentials.

Lines 145–161

SEND-PLAIN-TEXT

Displays a plain-text message to the user on the terminal screen and immediately ends the session transaction. This is used to communicate a final status or error message — such as a graceful sign-off acknowledgement — before returning control to the CICS environment.

Lines 162–176

POPULATE-HEADER-INFO

Assembles the standard header information displayed at the top of the sign-on screen, including application titles, the current date and time, and system identifiers, so that users see a consistent and accurately timestamped interface when they attempt to log in.

Lines 177–208

READ-USER-SEC-FILE

This paragraph performs the core authentication check by looking up the user's credentials in the User Security file and, upon successful verification, routes the authenticated user to the appropriate menu based on their role. If authentication fails for any reason, it redisplays the sign-on screen with a specific error message guiding the user on how to proceed.
