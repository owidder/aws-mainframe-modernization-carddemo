CBTRN01C.CBL

Batch program that reads daily credit card transactions and validates each transaction by verifying the card number and resolving it to a customer account, as a precursor to posting.

The program sequentially reads all transactions from the daily transaction file and, for each transaction, performs a two-step lookup: first it uses the card number to find the corresponding account and customer via a cross-reference file, then it retrieves the full account record from the account master file. Transactions where the card number cannot be found in the cross-reference are flagged and skipped, while transactions where the resolved account cannot be found in the account file are also flagged. The program appears to be an earlier or lighter version of CBTRN02C, focused on the validation and lookup phase rather than the full posting of balances — it opens the transaction posting file but does not appear to write to it in the visible code. All files are opened in read-only (INPUT) mode, suggesting this may be a validation/reconciliation pass rather than a full posting run.

Business Rules
  • Every transaction must have a valid, recognisable card number — if the card number cannot be found in the cross-reference file, the transaction is skipped and not posted
  • Every card number must resolve to a valid, existing account — if the account cannot be found in the account master file, the transaction is flagged with an error message
  • Transactions are processed strictly in the sequential order they appear in the daily transaction file — no sorting or prioritisation is applied
  • Any file I/O error (other than end-of-file) on the daily transaction file causes an immediate abnormal termination (abend) of the program, protecting data integrity
  • The card-to-account cross-reference is the authoritative source for linking a card number to an account and customer — the card number alone is not sufficient to identify an account
