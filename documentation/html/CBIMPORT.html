CBIMPORT.CBL

Import and normalise customer, account, card, and transaction data from a branch migration export file into the CardDemo system's target data stores.

CBIMPORT is the counterpart to CBEXPORT: it reads a structured, multi-record-type migration file produced by a source branch and splits it into five separate, normalised output files (Customer, Account, Card Cross-Reference, Card, and Transaction). Each record in the input file carries a type indicator ('C', 'A', 'X', 'D', 'T') that determines which target file it is routed to, with all relevant fields mapped and written accordingly. The program validates data integrity using checksums and tracks import statistics (records read and written per entity type) throughout the run. Any records with unrecognised record types are flagged and written to a dedicated error report file, ensuring a clean and auditable migration outcome.

Business Rules
  • Each record in the migration file must carry a valid record type indicator ('C', 'A', 'X', 'T', or 'D'); records with any other type are rejected to the error file and counted separately to flag data quality issues.
  • All five output files (Customer, Account, Cross-Reference, Transaction, Card) must be successfully opened before processing begins; failure to open any file causes an immediate abnormal termination to prevent partial or corrupt imports.
  • Customer records must carry full personal identification data including SSN, government-issued ID, date of birth, FICO credit score, and primary card-holder indicator, preserving regulatory and credit risk information across the migration.
  • The card cross-reference record (type 'X') must link a card number to both a customer ID and an account ID, maintaining the three-way relationship that is essential for card authorisation and account servicing.
  • Data integrity is validated using checksums after processing to ensure the imported data matches the source export, supporting reconciliation and audit requirements for the branch migration.
  • Import statistics are tracked at the record-type level (customers, accounts, cross-references, transactions, cards, errors) to provide a full reconciliation count for sign-off by operations and the receiving branch.
  • Any write failure to any output file causes an immediate abnormal termination, preventing silent data loss or partial record sets that would compromise the integrity of the migrated portfolio.
  • The program records the date and time of the import run, providing an audit trail that ties the imported data to a specific migration event for regulatory and operational purposes.
