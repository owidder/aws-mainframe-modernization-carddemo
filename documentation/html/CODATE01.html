CODATE01.CBL

Provide current date and time information to requesting services via IBM MQ messaging, acting as a centralised date/time service within the CardDemo credit card management system.

CODATE01 operates as a CICS-hosted MQ listener service that receives date/time enquiry requests from other system components via an IBM MQ input queue. Upon receiving a request, the program retrieves the current system date and time and returns the formatted response to the caller via a dedicated reply queue (CARD.DEMO.REPLY.DATE). The program processes messages in a continuous loop until no more messages are available, committing each transaction via CICS SYNCPOINT to ensure message integrity. Any processing errors are routed to a centralised error queue (CARD.DEMO.ERROR) for operational monitoring and fault management.

Business Rules
  • Each message retrieved from the input queue must be processed within a CICS SYNCPOINT boundary to guarantee exactly-once delivery and prevent message loss or duplication.
  • If the MQ input queue, output reply queue, or error queue cannot be opened at startup, the program must terminate immediately rather than process requests with incomplete infrastructure.
  • All error conditions (queue open failures, CICS retrieve failures) must be reported to the centralised CARD.DEMO.ERROR queue to ensure operational visibility across the CardDemo platform.
  • The program waits up to 5000 milliseconds (5 seconds) for a new message before concluding that no more messages are available and terminating gracefully.
  • The reply queue name is hardcoded as CARD.DEMO.REPLY.DATE, establishing a fixed service contract between this date utility and its consumers.
  • The program initialises as INITIAL, meaning each CICS invocation starts with a clean working storage state, ensuring no stale date/time data is returned from a previous execution.
