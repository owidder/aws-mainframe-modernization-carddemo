PAUDBLOD.CBL

Loading of outstanding authorization data from sequential files into the IMS database for recovery or initial population of the pending authorization database.

The program PAUDBLOD is the counterpart to the unload program PAUDBUNL and reads two sequential input files: one containing authorization summary records (root segments) and one containing authorization detail records (child segments). First, all root segments (authorization summaries per account) are read sequentially and inserted as parent segments into the IMS database. Subsequently, all child segments (authorization details) are read; for each detail record, the corresponding root record is first located in the IMS database by account ID, and then the detail record is inserted as a child segment. Already existing records (duplicates) are tolerated and logged without triggering an abend.

Business Rules
  • Root segments (authorization summaries) must be loaded into the IMS database before child segments (authorization details), as required by the hierarchical IMS structure.
  • For each child record, the associated root record must be locatable in the IMS database by account ID (ACCNTID) before the detail record can be inserted.
  • Duplicates (status 'II' = Duplicate Segment) are tolerated and logged for both root and child segments, but do not cause program termination – this enables idempotent restart runs.
  • Child records with a non-numeric account ID are skipped and not loaded into the database.
  • Any other database error (other than duplicate or success) causes an immediate program abend (ABEND) to ensure data consistency.
  • The program operates in IMS batch mode with PSB scheduling and supports checkpoint/restart mechanisms for restartability in case of errors.
