COBTUPDT.CBL

Batch utility program that maintains the Transaction Type reference table by processing a sequential input file to add, update, or delete transaction type codes and their descriptions.

COBTUPDT reads a sequential input file containing transaction type maintenance instructions and applies each record to the CARDDEMO.TRANSACTION_TYPE database table. Each input record carries an operation code (A=Add, U=Update, D=Delete) along with a two-character transaction type code and a 50-character description. The program processes all records sequentially until end-of-file, performing the corresponding database operation for each valid instruction. Any invalid operation code, missing record, or database error causes the program to abend with return code 4 and an error message, ensuring data integrity of the reference table.

Business Rules
  • Only three operation types are valid: A (Add), U (Update), D (Delete); any other value except the comment marker (*) causes an immediate abend with return code 4.
  • Lines prefixed with '*' are treated as comments and are silently ignored, allowing annotated input files.
  • A transaction type code (TR_TYPE) must already exist in the reference table for Update and Delete operations; if no matching record is found (SQLCODE +100), the program abends rather than silently continuing.
  • Any negative SQL error code on any database operation (Insert, Update, or Delete) causes an immediate abend, preventing partial or corrupt updates to the reference table.
  • The program processes records strictly sequentially with no rollback mechanism, meaning records processed before a failure are permanently committed to the database.
  • The transaction type code is exactly 2 characters and the description is capped at 50 characters, enforcing the data standards of the TRANSACTION_TYPE reference table.
  • This is a reference data maintenance program; changes to the TRANSACTION_TYPE table affect how transactions are classified and reported across the entire CardDemo system.
