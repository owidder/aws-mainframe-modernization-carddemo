COADM01C.CBL

Presents and manages the administrative navigation menu for authorised admin users in the CardDemo credit card management system.

When an admin user successfully logs in, this program displays a role-specific menu screen listing up to 10 administrative functions available within the CardDemo system. The user selects a numbered option, and the program validates the selection before transferring control to the corresponding administrative sub-program. If the selected option corresponds to a function that has not yet been installed or activated (marked as 'DUMMY'), the program informs the user that the option is unavailable rather than attempting to launch it. If no valid session context exists (communication area is empty), the user is redirected back to the sign-on screen, enforcing session integrity.

Business Rules
  • Only authenticated admin users with a valid session (non-empty communication area) may access the admin menu; unauthenticated or session-less users are immediately redirected to the sign-on screen.
  • A user-entered menu option must be numeric, non-zero, and must not exceed the total number of configured administrative options; any invalid entry results in an error message and the menu is re-displayed.
  • Administrative menu options flagged as 'DUMMY' are recognised as not yet installed; the system informs the user the option is unavailable and does not attempt to launch the corresponding program.
  • Pressing PF3 at any point returns the user to the sign-on screen, providing a controlled and secure exit from the admin menu.
  • The menu supports a maximum of 10 displayable administrative options; any options beyond 10 configured in the system are silently ignored in the display.
  • Control is transferred to sub-programs via CICS XCTL, passing the shared communication area to maintain session context and navigation history across the admin workflow.
  • Any key press other than Enter or PF3 is treated as invalid and results in an 'invalid key' error message, preventing unintended navigation actions.

Paragraph Overview

MAIN-PARA

MAIN-PARA is the central orchestration entry point of the admin menu program. It enforces session integrity, controls first-time versus returning screen display, routes user key presses to the appropriate business action, and ensures the CICS session is kept alive for continued admin navigation.

Lines 75–118

PROCESS-ENTER-KEY

This paragraph processes the admin user's menu selection when they press Enter, validating the chosen option number and either launching the corresponding administrative function or informing the user that the selected option is not yet available.

Lines 119–162

RETURN-TO-SIGNON-SCREEN

This paragraph handles the secure exit from the admin menu by redirecting the user back to the bank's sign-on screen, ensuring no admin session remains open without proper re-authentication. It acts as the controlled logout pathway, enforcing session integrity by always landing the user at a known, safe entry point.

Lines 163–174

SEND-MENU-SCREEN

This paragraph assembles and renders the administrative navigation menu screen for the authenticated admin user. It combines header information, the list of available administrative functions, and any status or error messages before presenting the fully built screen to the user.

Lines 175–191

RECEIVE-MENU-SCREEN

Captures the admin user's menu selection submitted from the administrative navigation screen. This step collects whatever option the user has entered before the system proceeds to validate and act on their choice.

Lines 192–204

POPULATE-HEADER-INFO

Prepares the standard header information displayed at the top of the administrative menu screen, including application titles, the current date and time, and identifiers that allow the user and support staff to identify which screen and transaction they are working in.

Lines 205–228

BUILD-MENU-OPTIONS

Constructs and populates the administrative menu screen by formatting each configured administrative function as a numbered display entry. This ensures the admin user sees a clean, sequentially numbered list of available system functions, limited to a maximum of 10 visible options.

Lines 229–269

PGMIDERR-ERR-PARA

This paragraph handles the scenario where an admin user selects a menu option that has not yet been installed or activated in the system. It informs the user that the chosen function is unavailable and returns them to the admin menu, maintaining their active session.
