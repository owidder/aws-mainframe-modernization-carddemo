COPAUS2C.CBL

Persistence of a fraud report or fraud de-marking for a credit card authorization transaction in the fraud database.

The program receives an authorization message with a fraud status indicator (report fraud or remove fraud) and writes it to the fraud table AUTHFRDS. All relevant transaction data (card number, merchant information, amounts, authorization codes) are stored together with the fraud status and the current reporting date. If an entry already exists for the same card and the same authorization timestamp (duplicate error -803), the existing record is updated with the new fraud status and the current date instead of being newly created. The program returns a success or error message to the calling program (COPAUS1C) via the Communication Area.

Business Rules
  • A transaction can either be flagged as fraudulent ('F') or an existing fraud report can be withdrawn ('R') – both actions are permanently logged in the fraud database.
  • If a fraud entry already exists for a card number and an authorization timestamp, it is updated (no duplicate) to allow status changes (e.g., fraud → no fraud).
  • The report date is always set to the current system date to document the point in time of the fraud decision in an audit-proof manner.
  • The authorization timestamp is reconstructed from a compressed time format of the original message (999999999 minus time value) and stored as a readable timestamp.
  • All relevant transaction data (merchant, amount, authorization code, POS entry mode, country code) are stored together with the fraud report to ensure complete fraud documentation.
  • The program is a pure service component with no user interface of its own – it is called exclusively by COPAUS1C (detail view) and returns the result via the COMMAREA.
