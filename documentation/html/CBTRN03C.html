CBTRN03C.CBL

Batch program that generates a formatted transaction detail report for credit card transactions within a specified date range, with subtotals by card account and grand totals.

The program reads a date parameter file to establish a reporting period (start date and end date), then sequentially reads all credit card transactions, filtering only those processed within that date range. For each qualifying transaction, it enriches the transaction data by looking up the card-to-account cross-reference, the transaction type description, and the transaction category description, then prints a formatted detail line on the report. The report is organised by card number, printing account-level subtotals whenever the card number changes, page-level subtotals every 20 lines with column headers repeated, and a grand total at the end of the report.

Business Rules
  • Only transactions whose processing date falls within the configured start date and end date (inclusive) are included in the report; transactions outside this range are silently skipped.
  • Transactions are grouped by card number; an account subtotal line is printed whenever the card number changes between consecutive transactions.
  • A page break with column headers reprinted is triggered every 20 detail lines to maintain report readability.
  • Each transaction line is enriched with a human-readable transaction type description and transaction category description sourced from reference tables, rather than displaying raw codes.
  • The card number is resolved to a customer account via the card cross-reference file, associating each transaction with the correct account on the report.
  • Page totals are accumulated into the grand total when a page break occurs, ensuring the grand total at the end of the report reflects all transactions in the reporting period.
  • The reporting period is driven entirely by an external date parameter file, making the report reusable for any date range without program changes.
  • The program abends (abnormal termination) if any reference file or the transaction file returns an unexpected I/O error, ensuring report integrity is not compromised by missing or corrupt data.
