CBACT04C.CBL

Batch interest calculation program that computes and posts monthly interest charges and fees to credit card accounts based on transaction category balances and account-specific interest rates.

The program reads transaction category balance records sequentially, grouping them by account. For each account, it retrieves the account master data and the card-to-account cross-reference, then looks up the applicable interest rate from a discount/rate group table based on the account's group classification and the transaction type and category. Where a non-zero interest rate applies, it calculates the interest amount for that transaction category balance and any associated fees, accumulating totals at the account level. When all categories for an account have been processed, it writes the computed interest and fees back to the account master file and generates corresponding transaction records to create an auditable trail of the interest charges applied.

Business Rules
  • Interest is calculated at the transaction category level: each combination of account, transaction type, and transaction category may carry a different interest rate.
  • Interest is only computed and fees only assessed when the applicable interest rate for that category is non-zero; zero-rate categories are skipped entirely.
  • Interest rates are determined by the account's assigned group (ACCT-GROUP-ID) combined with the transaction type code and transaction category code, allowing differentiated pricing across customer segments and spend categories.
  • Account balances are updated in batch at the end of processing each account's categories, ensuring all category-level interest amounts are accumulated before a single account master write is performed.
  • Each interest or fee charge generates a discrete transaction record, providing a complete audit trail of all system-generated charges.
  • The program accepts a processing date as an external parameter, enabling it to be run for specific statement or billing cycle dates rather than always using the current system date.
  • The card-to-account cross-reference must be resolved for every account processed, ensuring interest postings are correctly associated with the right account even when initiated from card-level data.
  • A sequential suffix counter ensures uniqueness of generated transaction IDs within a single batch run, preventing duplicate transaction records.
