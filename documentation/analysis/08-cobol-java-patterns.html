COBOL → Java Patterns

Concrete transformation recipes for every COBOL pattern found in CardDemo. Each section shows the original COBOL (with source reference) side-by-side with its Java/Spring equivalent. All Java examples assume the target stack: Spring Boot · Spring Batch · Spring Security · JPA/Hibernate · PostgreSQL.

Batch Patterns (JCL + Batch COBOL)

JCL → Spring Batch Job

Quick Reference
  • EXEC PGM= (JCL) — JCL step card that runs a batch COBOL program; DD statements assign physical datasets to DDNames

The JCL job card, EXEC PGM= steps, and DD statements map to a Spring Batch @Configuration class. File paths that were coded in JCL DD DSN= become application.yml properties.

JCL — POSTTRAN job
//POSTTRAN JOB (ACCT),'DAILY TXN',CLASS=A
//STEP010  EXEC PGM=CBTRN01C
//DALYTRAN DD DSN=PROD.DALYTRAN.FILE,
//            DISP=SHR
//DALYREJS DD DSN=PROD.DALYREJS.FILE,
//            DISP=(NEW,CATLG)
//STEP020  EXEC PGM=CBTRN02C,
//            COND=(0,NE,STEP010)
//TRANFILE DD DSN=PROD.TRANFILE,
//            DISP=(NEW,CATLG)
//ACCTFILE DD DSN=PROD.ACCTFILE,
//            DISP=SHR
//TCATBALF DD DSN=PROD.TCATBALF,
//            DISP=SHR
Java — Spring Batch configuration
@Configuration
public class TransactionPostingJobConfig {

  // DD DSN= → application.yml
  @Value("${carddemo.batch.dalytran-path}")
  private String dalytranPath;

  @Bean
  public Job postingJob(Step validateStep,
                        Step postStep) {
    return jobBuilder
        .get("POSTTRAN")
        .start(validateStep)   // STEP010 = CBTRN01C
        .next(postStep)        // STEP020 = CBTRN02C
        .build();
  }
  // COND=(0,NE,STEP010) → Spring Batch
  // stops automatically on FAILED step
}

VSAM KSDS (sequential) / PERFORM UNTIL AT END → Spring Batch ItemReader

Quick Reference
  • VSAM KSDS (sequential) — Sequential scan of a Key-Sequenced Dataset; reads all records in primary-key order via PERFORM UNTIL loop
  • PERFORM UNTIL AT END — Main batch loop verb: repeats a paragraph until a condition is true or end-of-file is reached

The canonical COBOL batch loop — open file, read until AT END, process each record, close file — maps directly to the Spring Batch Step chunk model. The framework drives the read loop; the developer only implements read(), process(), and write().

COBOL — CBTRN02C.cbl : L193–L230
PROCEDURE DIVISION.
    DISPLAY 'START OF EXECUTION...'
    PERFORM 0000-DALYTRAN-OPEN
    ...

    PERFORM UNTIL END-OF-FILE = 'Y'
        IF END-OF-FILE = 'N'
            PERFORM 1000-DALYTRAN-GET-NEXT
            IF END-OF-FILE = 'N'
                ADD 1 TO WS-TRANSACTION-COUNT
                PERFORM 1500-VALIDATE-TRAN
                IF WS-VALIDATION-FAIL-REASON = 0
                    PERFORM 2000-POST-TRANSACTION
                ELSE
                    PERFORM 2500-WRITE-REJECT-REC
                END-IF
            END-IF
        END-IF
    END-PERFORM.

    PERFORM 9000-DALYTRAN-CLOSE
    ...
    DISPLAY 'END OF EXECUTION...'

1000-DALYTRAN-GET-NEXT.
    READ DALYTRAN-FILE INTO DALYTRAN-RECORD.
    IF DALYTRAN-STATUS = '10'  ← EOF
        MOVE 'Y' TO END-OF-FILE
    ELSE IF DALYTRAN-STATUS <> '00'
        PERFORM 9999-ABEND-PROGRAM
    END-IF.
Java — Spring Batch Step (chunk-oriented)
// Spring Batch drives the loop — no PERFORM UNTIL needed
@Bean
public Step postingStep(
    ItemReader<DailyTransaction> reader,
    ItemProcessor<DailyTransaction,
                  PostingResult> processor,
    ItemWriter<PostingResult> writer) {

  return stepBuilder
      .<DailyTransaction, PostingResult>chunk(100)
      .reader(reader)      // null = EOF (= STATUS '10')
      .processor(processor) // validate + post logic
      .writer(writer)
      .listener(new JobExecutionListenerSupport() {
        public void beforeJob(JobExecution e) {
          log.info("START OF EXECUTION"); // DISPLAY
        }
        public void afterJob(JobExecution e) {
          log.info("END OF EXECUTION — status: {}",
                   e.getStatus());
        }
      })
      .build();
}

// ItemReader: return null signals EOF to the framework
@Override
public DailyTransaction read() {
  DailyTransaction record = delegate.read();
  return record; // null = no more records
}

OPEN / CLOSE → Spring Batch Resource Lifecycle

Quick Reference
  • OPEN / CLOSE — Opens a dataset for I/O before the read loop; closes it to flush buffers and release the resource after

COBOL explicitly opens and checks every file before use and closes every file after the loop. Spring Batch handles this via the ItemStream lifecycle: open() before the step, close() after.

COBOL — CBTRN02C.cbl : L236–L343
0000-DALYTRAN-OPEN.
    OPEN INPUT DALYTRAN-FILE
    IF DALYTRAN-STATUS = '00'
        MOVE 0 TO APPL-RESULT
    ELSE
        DISPLAY 'ERROR OPENING DALYTRAN'
        MOVE DALYTRAN-STATUS TO IO-STATUS
        PERFORM 9910-DISPLAY-IO-STATUS
        PERFORM 9999-ABEND-PROGRAM
    END-IF.

9000-DALYTRAN-CLOSE.
    CLOSE DALYTRAN-FILE
    IF DALYTRAN-STATUS = '00'
        MOVE 0 TO APPL-RESULT
    ELSE
        DISPLAY 'ERROR CLOSING DALYTRAN'
        PERFORM 9999-ABEND-PROGRAM
    END-IF.

* Repeated for each of the 5 other files
Java — Spring Batch handles open/close
// FlatFileItemReader (file-based path):
@Bean
public FlatFileItemReader<DailyTransaction> reader(
    @Value("${carddemo.batch.dalytran-path}")
    Resource resource) {

  return new FlatFileItemReaderBuilder<
              DailyTransaction>()
      .name("dalytranReader")
      .resource(resource)      // open() called by framework
      .fixedLength()
      .columns(...)
      .targetType(DailyTransaction.class)
      .build();
  // framework calls close() after step completes
  // IOException on open → step FAILED immediately
}

// JPA path (DB instead of file):
@Bean
public JpaCursorItemReader<DailyTransaction>
    dbReader(EntityManagerFactory emf) {
  return new JpaCursorItemReaderBuilder<>()
      .name("dalytranDbReader")
      .entityManagerFactory(emf)
      .queryString("SELECT t FROM DailyTransaction t
                    ORDER BY t.id")
      .build();
}

VSAM KSDS (random) / READ … INTO → repository.findById()

Quick Reference
  • VSAM KSDS (random) — Random lookup of a single record by primary key; INVALID KEY branch fires if the key is absent
  • READ … INTO — Reads one record from a file into a working-storage buffer area

Random-key reads — READ FILE INTO RECORD INVALID KEY … NOT INVALID KEY … — map to repository.findById() returning an Optional. The INVALID KEY branch becomes the orElseThrow() or orElse() path.

COBOL — CBTRN02C.cbl : L383–L430
* Look up card cross-reference:
    MOVE DALYTRAN-CARD-NUM TO FD-XREF-CARD-NUM
    READ XREF-FILE INTO CARD-XREF-RECORD
        INVALID KEY
            MOVE 100 TO WS-VALIDATION-FAIL-REASON
            MOVE 'INVALID CARD NUMBER FOUND'
              TO WS-VALIDATION-FAIL-REASON-DESC
        NOT INVALID KEY
            CONTINUE
    END-READ.

* Look up account with credit-limit check:
    MOVE XREF-ACCT-ID TO FD-ACCT-ID
    READ ACCOUNT-FILE INTO ACCOUNT-RECORD
        INVALID KEY
            MOVE 101 TO WS-VALIDATION-FAIL-REASON
            MOVE 'ACCOUNT RECORD NOT FOUND'
              TO WS-VALIDATION-FAIL-REASON-DESC
        NOT INVALID KEY
            COMPUTE WS-TEMP-BAL =
                ACCT-CURR-CYC-CREDIT
              - ACCT-CURR-CYC-DEBIT
              + DALYTRAN-AMT
            IF ACCT-CREDIT-LIMIT < WS-TEMP-BAL
                MOVE 102 TO WS-VALIDATION-FAIL-REASON
            END-IF
    END-READ.
Java — repository + Optional
// Look up card cross-reference
CardXref xref = cardXrefRepository
    .findById(tran.getCardNum())
    .orElseThrow(() -> new ValidationException(
        100, "INVALID CARD NUMBER FOUND"));

// Look up account
Account acct = accountRepository
    .findById(xref.getAcctId())
    .orElseThrow(() -> new ValidationException(
        101, "ACCOUNT RECORD NOT FOUND"));

// Credit-limit check (CBTRN02C:L403)
BigDecimal tempBal = acct.getCurrCycCredit()
    .subtract(acct.getCurrCycDebit())
    .add(tran.getAmount());

if (acct.getCreditLimit().compareTo(tempBal) < 0) {
    throw new ValidationException(
        102, "OVERLIMIT TRANSACTION");
}

// Expiration check (CBTRN02C:L414)
if (acct.getExpirationDate()
        .isBefore(tran.getOrigTimestamp()
                      .toLocalDate())) {
    throw new ValidationException(
        103, "TRANSACTION RECEIVED AFTER ACCT EXPIRATION");
}

WRITE / REWRITE → repository.save()

Quick Reference
  • WRITE … FROM — Inserts a new record into a file from a working-storage buffer
  • REWRITE … FROM — Replaces the last-read record in a file with updated working-storage data

Both WRITE (INSERT) and REWRITE (UPDATE) collapse into a single repository.save(entity) call in JPA — Hibernate decides INSERT vs UPDATE based on whether the entity is managed. For flat-file output, use FlatFileItemWriter.

COBOL — CBTRN02C.cbl : L510–L575
* INSERT new balance record (2700-A):
    WRITE FD-TRAN-CAT-BAL-RECORD
          FROM TRAN-CAT-BAL-RECORD
    IF TCATBALF-STATUS = '00'
        CONTINUE
    ELSE
        DISPLAY 'ERROR WRITING TRANSACTION BALANCE'
        PERFORM 9999-ABEND-PROGRAM
    END-IF.

* UPDATE existing account record (2800):
    REWRITE FD-ACCTFILE-REC
            FROM ACCOUNT-RECORD
    IF ACCTFILE-STATUS = '00'
        CONTINUE
    ELSE
        DISPLAY 'ERROR REWRITING ACCOUNT'
        PERFORM 9999-ABEND-PROGRAM
    END-IF.

* INSERT new transaction (2900):
    WRITE FD-TRANFILE-REC
          FROM TRAN-RECORD
    IF TRANFILE-STATUS <> '00'
        PERFORM 9999-ABEND-PROGRAM
    END-IF.
Java — JPA save() handles INSERT + UPDATE
@Transactional
public void postTransaction(DailyTransaction dt,
                             CardXref xref,
                             Account acct) {

    // 2700 — INSERT or UPDATE TranCatBalance
    var key = new TranCatKey(
        xref.getAcctId(),
        dt.getTypeCd(), dt.getCatCd());
    TranCatBalance catBal = catBalRepo
        .findById(key)
        // WRITE (INSERT) if not found:
        .orElse(new TranCatBalance(key,
                                   BigDecimal.ZERO));
    catBal.setBalance(
        catBal.getBalance().add(dt.getAmount()));
    catBalRepo.save(catBal); // INSERT or REWRITE

    // 2800 — REWRITE account
    acct.setCurrBal(
        acct.getCurrBal().add(dt.getAmount()));
    accountRepo.save(acct); // REWRITE

    // 2900 — WRITE transaction
    Transaction tran = mapper.toEntity(dt);
    tran.setProcTimestamp(LocalDateTime.now());
    transactionRepo.save(tran); // WRITE
    // IOException → RuntimeException →
    // Step catches it as FAILED (no need to check status)
}

Find-or-Create Pattern (2700-UPDATE-TCATBAL)

A common COBOL pattern: read a record; if INVALID KEY (not found) create it, otherwise update it. JPA's findById().orElse(new …) plus save() is the idiomatic replacement.

COBOL — CBTRN02C.cbl : L474–L541
2700-UPDATE-TCATBAL.
    MOVE 'N' TO WS-CREATE-TRANCAT-REC
    READ TCATBAL-FILE INTO TRAN-CAT-BAL-RECORD
        INVALID KEY
            DISPLAY 'TCATBAL record not found'
            MOVE 'Y' TO WS-CREATE-TRANCAT-REC
    END-READ.

    IF TCATBALF-STATUS = '00' OR '23'
        MOVE 0 TO APPL-RESULT
    ELSE
        PERFORM 9999-ABEND-PROGRAM
    END-IF.

    IF WS-CREATE-TRANCAT-REC = 'Y'
        PERFORM 2700-A-CREATE-TCATBAL-REC
    ELSE
        PERFORM 2700-B-UPDATE-TCATBAL-REC
    END-IF.

2700-A-CREATE-TCATBAL-REC.
    INITIALIZE TRAN-CAT-BAL-RECORD
    ADD DALYTRAN-AMT TO TRAN-CAT-BAL
    WRITE FD-TRAN-CAT-BAL-RECORD ...

2700-B-UPDATE-TCATBAL-REC.
    ADD DALYTRAN-AMT TO TRAN-CAT-BAL
    REWRITE FD-TRAN-CAT-BAL-RECORD ...
Java — findById().orElse() + save()
// The entire 2700 paragraph collapses to 4 lines:
private void updateCatBalance(CardXref xref,
                               DailyTransaction dt) {
    var key = new TranCatKey(
        xref.getAcctId(),
        dt.getTypeCd(),
        dt.getCatCd());

    TranCatBalance rec = catBalRepo
        .findById(key)
        // STATUS '23' / INVALID KEY path:
        .orElseGet(() -> {
            log.debug("TranCatBalance not found — "
                    + "creating: {}", key);
            return new TranCatBalance(key,
                                     BigDecimal.ZERO);
        });

    // ADD DALYTRAN-AMT TO TRAN-CAT-BAL
    rec.setBalance(
        rec.getBalance().add(dt.getAmount()));

    // WRITE or REWRITE — JPA decides automatically
    catBalRepo.save(rec);
}

Multiple Output Files → CompositeItemWriter

When a COBOL batch program writes to several output files in one pass (like CBACT01C.cbl writing to OUTFILE, ARRYFILE, VBRCFILE), use CompositeItemWriter to fan out to multiple writers.

COBOL — CBACT01C (three output files per record)
PERFORM UNTIL END-OF-FILE = 'Y'
    PERFORM 1000-ACCTFILE-GET-NEXT
    IF END-OF-FILE = 'N'
        PERFORM 1100-DISPLAY-ACCT-RECORD
        PERFORM 1300-POPUL-ACCT-RECORD
        WRITE FD-ACCTFILE-REC         ← OUTFILE
              FROM OUT-ACCT-REC
        PERFORM 1400-POPUL-ARRAY-RECORD
        WRITE FD-ARRY-RECORD          ← ARRYFILE
              FROM ARR-ARRAY-REC
        PERFORM 1500-POPUL-VBRC-RECORD
        WRITE FD-VBRC-RECORD1         ← VBRCFILE
              FROM VBRC-REC1
        WRITE FD-VBRC-RECORD2
              FROM VBRC-REC2
    END-IF
END-PERFORM.
Java — CompositeItemWriter
@Bean
public CompositeItemWriter<AccountExportResult>
    compositeWriter(
      AccountFlatFileWriter flatWriter,
      AccountArrayFileWriter arrayWriter,
      AccountVbrFileWriter vbrWriter) {

  return new CompositeItemWriterBuilder<
                AccountExportResult>()
      .delegates(flatWriter,   // OUTFILE
                 arrayWriter,  // ARRYFILE
                 vbrWriter)    // VBRCFILE
      .build();
}

// Each writer receives the same
// AccountExportResult and extracts its part:
@Component
public class AccountFlatFileWriter
    implements ItemWriter<AccountExportResult> {
  @Override
  public void write(Chunk<? extends
                    AccountExportResult> chunk) {
    for (var r : chunk.getItems())
      flatFileWriter.write(r.getFlatRecord());
  }
}

CICS Patterns

EXEC CICS RECEIVE MAP → @RequestBody

Quick Reference
  • EXEC CICS RECEIVE MAP — Reads terminal screen input (BMS map) into a COBOL data structure for processing

EXEC CICS RECEIVE MAP reads the BMS map data from the terminal into a COBOL copybook structure. In REST, the equivalent is a JSON request body deserialized into a DTO by Jackson.

COBOL — COACTUPC.cbl : L1040
EXEC CICS RECEIVE
    MAP    (LIT-THISMAP)
    MAPSET (LIT-THISMAPSET)
    INTO   (COACUP0AI)      ← screen input struct
    RESP   (WS-RESP-CD)
    RESP2  (WS-REAS-CD)
END-EXEC.

* Fields are now in copybook structure:
MOVE ACTIDINL OF COACUP0AI TO WS-ACCT-ID
MOVE ACSTTUSI OF COACUP0AI TO WS-ACCT-STATUS
MOVE ACRDLIMI OF COACUP0AI TO WS-CREDIT-LIMIT
Java — Spring MVC @RequestBody
// DTO mirrors the BMS map fields
public record UpdateAccountRequest(
    @NotNull Long accountId,
    @NotBlank @Size(max = 1)
    String activeStatus,
    @NotNull @DecimalMin("0")
    BigDecimal creditLimit
    // … further fields from COACUP0AI
) {}

@RestController
@RequestMapping("/api/accounts")
public class AccountController {

  @PutMapping("/{id}")
  public ResponseEntity<AccountDto> update(
      @PathVariable Long id,
      @RequestBody @Valid
      UpdateAccountRequest req) {

    // Fields land in req — same as
    // MOVE ACTIDINL OF COACUP0AI TO WS-ACCT-ID
    AccountDto updated =
        accountService.update(id, req);
    return ResponseEntity.ok(updated);
  }
}

EXEC CICS SEND MAP → ResponseEntity

Quick Reference
  • EXEC CICS SEND MAP — Fills a BMS map layout with output data and sends the rendered screen to the terminal

EXEC CICS SEND MAP fills a BMS map and sends it to the terminal. In REST, the equivalent is a ResponseEntity<DTO> serialized to JSON by Jackson. For server-side rendering, use a Thymeleaf template.

COBOL — COSGN00C.cbl : L151
* Fill the output map structure:
MOVE WS-MESSAGE  TO ERRMSGSO OF COSGN0AO
MOVE WS-TRANID   TO TRNNAMEO OF COSGN0AO
MOVE -1          TO USERIDL  OF COSGN0AI

* Send the map to the terminal:
EXEC CICS SEND
    MAP    ('COSGN0A')
    MAPSET ('COSGN00')
    FROM   (COSGN0AO)    ← output struct
    ERASE
    CURSOR
END-EXEC.

* Wait for next operator input — COBOL suspends
EXEC CICS RETURN
    TRANSID (WS-TRANID)
    COMMAREA(CARDDEMO-COMMAREA)
END-EXEC.
Java — ResponseEntity (REST) or Thymeleaf
// REST API response:
public record LoginResponse(

EXEC CICS READ / REWRITE → Repository

Quick Reference
  • EXEC CICS READ — Reads one VSAM record by key via CICS file control; RESP return code replaces file status
  • EXEC CICS REWRITE — Updates a previously-read CICS-controlled VSAM record in place; must follow a CICS READ

Online programs read VSAM datasets via EXEC CICS READ DATASET(…) RIDFLD(…). The RESP return code replaces file status. In Java, a findById() call on a JPA repository is the direct equivalent; RESP=16 (NOTFND) becomes Optional.isEmpty().

COBOL — COSGN00C.cbl : L211–L257
READ-USER-SEC-FILE.
    EXEC CICS READ
        DATASET   (WS-USRSEC-FILE)
        INTO      (SEC-USER-DATA)
        LENGTH    (LENGTH OF SEC-USER-DATA)
        RIDFLD    (WS-USER-ID)       ← key
        KEYLENGTH (LENGTH OF WS-USER-ID)
        RESP      (WS-RESP-CD)
        RESP2     (WS-REAS-CD)
    END-EXEC.

    EVALUATE WS-RESP-CD
        WHEN 0               ← DFHRESP(NORMAL)
            IF SEC-USR-PWD = WS-USER-PWD
                PERFORM LOGIN-OK
            ELSE
                PERFORM WRONG-PASSWORD
            END-IF
        WHEN 13              ← DFHRESP(NOTFND) = 16
            PERFORM USER-NOT-FOUND
        WHEN OTHER
            PERFORM CICS-ERROR
    END-EVALUATE.
Java — Spring Security UserDetailsService
@Service
public class AuthenticationService
        implements UserDetailsService {

  @Override
  public UserDetails loadUserByUsername(
      String userId) {
    // EXEC CICS READ DATASET(USRSEC)
    //   RIDFLD(WS-USER-ID) RESP(WS-RESP-CD)
    return userRepository
        .findByUserId(userId.toUpperCase())
        // WHEN 0 (NORMAL): user found
        // WHEN 13 (NOTFND): user not found
        .orElseThrow(() ->
            new UsernameNotFoundException(
                "User not found. Try again ..."));
    // WHEN OTHER (CICS error):
    // DataAccessException propagates automatically
  }
}

// Password check (COSGN00C:L223 SEC-USR-PWD = WS-USER-PWD)
// is performed by Spring Security's
// DaoAuthenticationProvider using BCryptPasswordEncoder
// — plaintext comparison is replaced by BCrypt.verify()

XCTL / RETURN TRANSID → HTTP Redirect

Quick Reference
  • EXEC CICS XCTL — Transfers control to another CICS program, passing the COMMAREA; the caller does not regain control
  • EXEC CICS RETURN TRANSID — Ends the pseudo-conversation; queues the specified transaction ID to activate on the next terminal input

EXEC CICS XCTL PROGRAM(…) transfers control to another CICS program, passing the COMMAREA. EXEC CICS RETURN TRANSID(…) suspends the current transaction and waits for the next terminal input. In REST, program-to-program transfer becomes an HTTP redirect or a service call.

COBOL — COSGN00C.cbl : L231–L238

IF CDEMO-USRTYP-ADMIN
    EXEC CICS XCTL
        PROGRAM ('COADM01C')  ← admin menu
        COMMAREA(CARDDEMO-COMMAREA)
    END-EXEC
ELSE
    EXEC CICS XCTL
        PROGRAM ('COMEN01C')  ← user menu
        COMMAREA(CARDDEMO-COMMAREA)
    END-EXEC
END-IF.

* Keep transaction alive for next input:
EXEC CICS RETURN
    TRANSID (WS-TRANID)
    COMMAREA(CARDDEMO-COMMAREA)
    LENGTH  (LENGTH OF CARDDEMO-COMMAREA)
END-EXEC.

    authManager.authenticate(

// ByteBuffer gives both views of the same bytes:
private String decodeIoStatus(String ioStatus) {
  if (ioStatus == null || ioStatus.length() < 2)
    return "????";

  byte[] bytes = ioStatus.getBytes(
      StandardCharsets.ISO_8859_1);
  ByteBuffer buf = ByteBuffer.wrap(bytes);

  // TWO-BYTES-BINARY view (S9(4) COMP):
  short binary = buf.getShort(0);

  // TWO-BYTES-ALPHA view:
  char left  = (char)(bytes[0] & 0xFF);
  char right = (char)(bytes[1] & 0xFF);

  if (!Character.isDigit(left)) {
    return "  " + ioStatus.substring(0, 2);
  } else {
    return String.format("%04d", binary);
  }
}

Error Handling

ABEND / CEE3ABD / PERFORM 9999-ABEND-PROGRAM → noSkip + RuntimeException

Quick Reference
  • ABEND / CEE3ABD — Abnormally terminates the program with a numeric abend code; dumps the region and kills the JES job
  • PERFORM 9999-ABEND-PROGRAM — CardDemo convention: paragraph that calls CEE3ABD with code 999 on any unrecoverable I/O error

CardDemo abends on any I/O error: it calls 9999-ABEND-PROGRAM, which calls the CEE3ABD system routine with abend code 999, terminating the entire job.
